# 自动日记本 · astrbot_plugin_auto_diary

> 仓库：https://github.com/feng20010612-glitch/astrbot_plugin_auto_diary

把和 AI 的对话，自动整理成日记。

聊完安静一段时间后，插件会调用当前使用的模型，把这段对话以**第一人称**写成一篇日记，存在本地 SQLite 里。一天一篇，越写越完整，不是流水账。

## 特性

- **自动整理**：对话结束后静默工作，不需要手动操作
- **一天一篇**：同一天的日记会被整合更新，而不是堆成一堆碎片
- **数据自持**：默认存在插件自己的数据目录，卸载插件也不会弄丢/带走别人的日记
- **可配置人设**：可以给模型一句人设提示词，让它用特定身份、特定口吻写日记
- **不干扰对话**：全流程后台执行，异常只写日志，不会影响正常回复
- **表结构通用**：`entries` 表字段直白（日期 / 标题 / 正文 / 标签 / 时间），导出方便

## 安装

1. 把 `astrbot_plugin_auto_diary` 整个文件夹放进 AstrBot 的 `data/plugins/` 目录
2. 重启 AstrBot（或在 WebUI 里重载插件）
3. 在插件配置页确认「启用自动日记」是开着的

依赖：无。只用 Python 标准库 + AstrBot 自带接口。

## 配置

在 AstrBot 的插件配置页里修改：

| 配置项 | 类型 | 默认 | 说明 |
|--------|------|------|------|
| `enabled` | bool | `true` | 是否启用自动日记 |
| `db_path` | string | 空 | 日记数据库路径；留空 = 插件数据目录 |
| `scope` | string | `private` | `private` 只记私聊 / `all` 群聊也记 |
| `mode` | string | `append` | `append` 追加分段（带时间戳）/ `merge` 整合成一篇 |
| `group_by` | string | `none` | 分组方式：`none` 全合成一篇 / `platform` 按平台 / `session` 按会话 |
| `trash_days` | string | `30` | 回收站保留天数：`7` / `30` / `90` / `0`（永久保留） |
| `idle_minutes` | int | `10` | 对话安静多少分钟后开始整理 |
| `persona` | string | 空 | 写日记时的人设提示词 |
| `title_template` | string | `日记 · {date}` | 日记标题模板，支持 `{date}` `{persona}` |

### 关于称呼

插件交给模型的对话记录长这样：

```
对方：今天天气不错
我：嗯，是不错。
```

这两个词只是**记录用的记号**，不是称呼——怎么写进日记完全由机器人的**人设**决定，提示词里也明确要求不要照抄。所以换人设之后，日记里的称呼会自然跟着变，不需要额外配置。

### 关于排查问题

插件会在自己的数据目录里写一份 `debug.log`，记录收到的对话、被跳过的原因、模型返回长度和异常信息，出问题时可以先翻它。

### 关于 `persona`

`persona` 决定日记用谁的口吻写，优先级从高到低：

1. **填了 `persona`** → 就用你写的这段设定
2. **留空（推荐）** → 自动沿用机器人当前会话的人设（会依次尝试四种取法，尽量兼容不同版本的 AstrBot），所以日记的口吻和标题里的 `{persona}` 都会跟角色一致
3. **取不到人设**（比如没配人格） → 退回到通用的「AI 助手」口吻

> 也就是说，通常留空就行——机器人是什么人设，日记就是什么语气。

### 关于 `mode`

- **`append`（默认）**：把当天已写的内容和新的对话一起交给模型，重写成一篇连贯的日记。读起来最顺，但旧内容会被改写。
- **`append`**：每次整理出来的内容直接追加到当天日记后面，并标上 `〔HH:MM〕`。同一篇里能看出「几点写的」这一段，信息一条都不会丢。
- **`merge`**：把旧内容和新对话一起交给模型，重写成一篇连贯的日记。

> 一天只写一篇：`append` 会把多段按时间叠在同一篇里，`merge` 则会不断把它改写成一篇完整的。

### 关于标题模板

默认是 `{persona}的日记本 · {date}`，其中：

- `{date}` → 月-日，例如 `10-10`
- `{persona}` → 当前人设的名字（取不到时用 `AI` 顶上）

如果机器人会切换人设，建议写成 `{persona}的日记本 {date}` 之类，这样标题也能看出来是谁记的。

### 关于分组

`group_by` 决定「哪些对话写进同一篇」：

| 值 | 效果 |
|----|------|
| `none`（默认） | 不管哪个平台、哪个会话，当天的对话都合成一篇 |
| `platform` | 按平台分开：QQ 一篇、网页一篇、Telegram 一篇…… |
| `session` | 按会话分开：每个私聊、每个群各自一条日记线（最细） |

> 选好之后就像人设一样各自记账，同一天里互不打扰。标签里分别记成 `plat:平台名` / `sess:会话标识`。
>
> 每条线有**各自的待写队列和安静计时**：A 会话在聊，不影响 B 会话该什么时候落笔。

### 关于人设切换

插件按**人设**分开记录：

- 同一个人设，一天只有一篇（`append` 就往后叠，`merge` 就重写这一篇）
- 换了人设之后，会**另起一篇**，两个角色的日记不会混在一起

实现上是在标签里加了一个 `persona:<人设名>` 标记，你不管它也行。

### 关于 `idle_minutes`

调小会让日记更新更及时，但一段没聊完的话容易被拆成好几篇；调大则一篇更完整，但等待更久。默认 10 分钟比较平衡。

## 命令

| 命令 | 说明 |
|------|------|
| `/读日记` | 看今天的日记 |
| `/读日记 昨天` | 看昨天的（`前天` 也可以） |
| `/读日记 2026-10-09` | 看指定日期 |
| `/读日记 10-09` | 看今年某月某日 |
| `/读日记 最近` | 列出最近写过的 10 篇 |
| `/读日记 搜索 咖啡` | 在日记正文里搜关键词 |
| `/写日记` | 不等空闲，立刻把攒下的对话整理成日记 |
| `/暂停日记` | 暂停记录（已攒下的内容保留） |
| `/恢复日记` | 恢复记录 |

> 参数认不出来的时候会当成关键词搜索；什么也没找到就回一段用法说明。

## 自带页面

插件带一个 Web 页面，在 AstrBot 面板里就能翻日记，不用敲命令：

- **日历视图**：写过日记的日期会带一个小圆点，点日期直接看那天写了什么
- **自由翻阅**：可以往前翻任意月份，也有「回到今天」
- **全文搜索**：顶部搜索框能在所有日记正文里找关键词
- **最近列表**：一键列出最近写过的日记
- **阅读偏好**：正文的字体和字号可以自己调（微软雅黑 / 宋体 / 楷体 / 黑体 / 仿宋 / 等线，字号 12–22px），选择存在插件目录（`prefs.json`），刷新或换浏览器都还在
- **编辑**：页面上直接改日记正文，不用碰数据库
- **导出**：一键导出 Markdown / TXT / JSON
- **那年今日**：翻出往年今天写过的日记
- **删除数据**：「删除这天」删掉某一天的日记，「清空全部日记」一键清空（都有二次确认，删完还能一键撤销）
- **随时静音**：`/暂停日记` 停止记录，`/恢复日记` 继续

打开方式：AstrBot 面板 → 插件 → 自动日记本 → 页面 → 「日记本」。

页面调用的只读接口：

| 接口 | 说明 |
|------|------|
| `GET /stats` | 总篇数、起始日期、总字数 |
| `GET /dates?start=&end=` | 某时间段里哪些日期有日记 |
| `GET /entry?date=YYYY-MM-DD` | 某一天的完整日记 |
| `GET /list?limit=&offset=` | 按时间倒序列出日记 |
| `GET /search?q=&limit=` | 全文搜索 |
| `POST /delete` | 删除数据：`{"date":"2026-10-10"}` 删某天，`{"all":true}` 清空 |
| `POST /update` | 改日记正文：`{"id":12,"content":"..."}` |
| `GET /export?format=md` | 导出全部（`md` / `txt` / `json`） |
| `GET /onthisday` | 往年今天的日记 |
| `GET /prefs` `POST /prefs` | 读取 / 保存页面偏好（字体、字号） |
| `POST /restore` | 撤销删除：`{"ids":[1,2]}`，或 `{"all":true}` 恢复全部 |
| `GET /trash` | 回收站：列出被软删除的日记 |
| `POST /trash/empty` | 彻底清空回收站（不可恢复） |

### 关于删除

页面上的删除都是**软删除**——记录还在 `entries` 表里，只是把 `deleted` 标成 1，页面上不再显示。所以删错了不要紧：

- 删错了不要紧：侧边栏的「回收站」里都在，可以逐篇恢复或一键全恢复
- 回收站默认保留 30 天（`trash_days` 可改），过期的会被自动彻底删除；也可以在里面点「彻底清空」立刻删干净
- 也可以用 `POST /restore`（带 `ids` 或 `all`）随时救回来

想彻底清干净的话，直接操作数据库把那些行删掉即可（或者把 `diary.db` 整个删了，插件会重新建一个空的）。

## 工作原理

```
用户消息 ──▶ AI 回复
                │
                ▼
        on_agent_done 事件
                │
                ▼
        攒进内存队列（最多 40 轮）
                │
        安静满 idle_minutes 分钟？
                │ 是
                ▼
    调用模型 → 第一人称日记
                │
                ▼
    写入 SQLite（当天有则更新，无则新建）
```

- 只在**对话结束**时收集内容，不打断生成过程
- 用「安静时长」而不是「定时轮询」来决定何时落笔，更贴近真实的聊天节奏
- 同一天多次整理会**整合**成一篇连贯的日记，而不是追加时间戳

## 数据在哪

默认路径（`db_path` 留空时）：

```
AstrBot/data/plugin_data/astrbot_plugin_auto_diary/diary.db
```

表结构：

```sql
CREATE TABLE entries (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    date       TEXT NOT NULL,          -- YYYY-MM-DD
    title      TEXT NOT NULL DEFAULT '',
    content    TEXT NOT NULL DEFAULT '',   -- 日记正文
    mood       TEXT NOT NULL DEFAULT '',
    weather    TEXT NOT NULL DEFAULT '',
    location   TEXT NOT NULL DEFAULT '',
    tags       TEXT NOT NULL DEFAULT '',   -- 默认 auto-diary
    deleted    INTEGER NOT NULL DEFAULT 0,
    deleted_at TEXT,
    created_at TEXT NOT NULL DEFAULT (datetime('now','localtime')),
    updated_at TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
```

表结构很通用，导出或者接别的工具都没问题。

## 常见问题

**Q：为什么聊完没有立刻出现日记？**
A：设计如此。默认要等对话安静 10 分钟才落笔，避免把没聊完的话切成好几篇。想立刻看就用 `/写日记`。

**Q：会不会很费模型调用？**
A：不会。一小时内聊了十轮，也只会调用一次模型（等安静之后统一整理）。

**Q：多人同时聊会串吗？**
A：不会。每个会话的事件各自触发，攒的内容按时间顺序合并，日记是当天汇总的一篇。

**Q：日记写错了想改？**
A：直接改数据库里的 `content` 就行；或者删掉当天的记录，下次会自动重新生成。
